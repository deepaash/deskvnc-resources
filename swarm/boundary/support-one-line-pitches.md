# DeskVNC Support, one line at a time

Seven pitches, each aimed at a different reader. All under 140 characters.
All true to the verified facts in the project README. Use as written, or as
starting material for posts, directory blurbs, and short pitches.

## Helpdesk operator

Take over a customer's desktop in a single click. No account for either side,
recipient approves every session and can revoke at any time.

## MSP

Support any client's machine via VNC, RDP or SSH. Boundary invites expire in a
single lookup and the recipient approves each session.

## Support engineer

Reach a customer's machine over Boundary: direct encrypted path first, relay
fallback, no install on the target, recipient approves.

## Developer debugging a remote machine

Paste a Boundary invite or four-group code, get a remote desktop over VNC, RDP
or SSH, and let the recipient approve.

## Team lead

Hand a signed DeskVNC Support app to anyone, get a Boundary code back in chat,
and let them approve when you connect. No accounts anywhere.

## IT generalist at a small business

DeskVNC Support ships signed and notarized, hands off a session through a
Boundary code, and never asks the recipient to create an account.

## Open-source enthusiast evaluating clients

MIT or Apache-2.0, runs on macOS, Windows, and Linux. Boundary support hands
off a session through a one-shot code with consent.
